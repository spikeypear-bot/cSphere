# Test cases: EO-C2 (a request must describe a real, future event)

Owner: Jillian · Story on **Sprint Backlog 4** (added under the Week 7 Guide to Managing Changes, Scenario 2; EO02 stays Done) · Test-case lane `EO-C2-TC1…TC3` on **Test Cases – Sprint 4**.

This is the repository copy of the Sheet entries, in the IS212 Week 4 template, plus every acceptance criterion traced to its automated tests.

The cases came from Week 4's five steps:
1. The workflow: draft → submit → clarification → resubmit → approve.
2. Happy path: a valid request, including an overnight event.
3. Cross-cutting: the server enforces the rules when the page is bypassed.
4. Negative: past dates, no duration, nobody attending, decimals.
5. Boundary and conflict: exactly now, one minute either side, the same moment in another time zone, and the start passing while the request waits or the page is open.

**Execution record:** all three cases were last executed on 24 Oct 2026 on branch `feat/eo-c2-request-date-validation`, status **Pass**, automated in CI.
