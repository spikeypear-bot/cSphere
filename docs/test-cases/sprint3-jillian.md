# Sprint 3 test cases: EC-NEW2, EC08, EO04

Owner: Jillian · Stories on **Sprint Backlog 3** · Test-case lanes on **Test Cases - Sprint 3** (IDs `EC-NEW2-TC1`…, `EC08-TC1`…, `EO04-TC1`…).

This page is the repository copy of those Sheet entries, in the IS212 Week 4 test-case template (*one specification, many executions*), plus a matrix tracing **every** acceptance criterion to the automated tests that check it. The test cases were derived with Week 4's five steps:
1. Visualise the workflow.
2. Happy path.
3. Cross-cutting expectations (role access, the same status everywhere).
4. Negative cases.
5. Boundary and conflict cases.

Each test case's **Remarks** names the automated tests that execute it, so the Sheet, the ACs and the code point at each other.

**How to read the automated-test names.** Test names start with the story, the ACs and the kind of case, for example `EC08 AC26, AC27 (conflict): …`. The layers are:

| Layer | Where | What it runs against |
|---|---|---|
| Unit | `backend/…/*Test.java` tagged `unit` | Mockito stubs and mocks, fixed clock |
| Integration | `backend/…/*Test.java` tagged `integration` | Real Spring, real PostgreSQL |
| Component | `frontend/src/**/*.test.tsx` | jsdom, `fetch` stubbed |
| E2E | `frontend/e2e/*.spec.ts` | Real browser against the packaged jar, the built frontend and PostgreSQL |

The whole-project story → test matrix is `docs/test-traceability.md`, generated by `.github/scripts/traceability.py`.

**Execution record.** Every case below was last executed on 16 Oct 2026 on branch `test/week9-testing-traceability`. The cases run automatically in CI on every pull request; E2E runs against the packaged build.
